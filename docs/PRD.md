# 콘텐츠 스튜디오 — 1단계 「아이디어」 PRD

- 상태: 개정 3 (2차 독립 검증 A·B·C 반영, 사용자 검토 전)
- 이 문서 하나만 읽고 구현·검증할 수 있도록 대화에서 나온 전제를 모두 적었다.
- 모든 UI 문구는 한국어다. 「」·따옴표 안의 문구는 예시이며 정확한 문구는 디자인 단계에서 정한다.
- **(제안값)** 은 사용자가 확정하지 않았지만 검증 가능한 기준을 위해 작성자가 정한 수치다. §11에 모아 두었고, 바뀌면 해당 완료 기준의 수치도 함께 바꾼다.

## 1. 배경

**콘텐츠 스튜디오**는 Obsidian **데스크톱** 플러그인이다. 한 사람의 작가가 아이디어 하나로 LinkedIn·Threads·인스타그램(카드뉴스·릴스)·뉴스레터·쇼츠 콘텐츠를 만든다.

| 단계 | 내용 | 이 PRD |
|---|---|---|
| 1단계 아이디어 | 메시지를 찾고, 글의 얼개를 정한다. 확정 후 같은 노트에서 초안을 쓰기 시작한다 | **대상** |
| 2단계 | 쓴 글을 고친다 | 제외 |
| 이후 | 채널별 글쓰기·발행·관리 | 제외 |

사용자는 글을 Obsidian 편집기에서 직접 쓴다. 1단계는 "무엇을 말할지(메시지)"와 "어떤 순서로 말할지(얼개)"를 정하는 작업 공간이다.

### 새로 만드는 이유

- 같은 이름의 기존 저장소(`github.com/logos1012/obsidian-content-studio`)가 있으나 사용자가 만족하지 못해 **처음부터 새로 만든다. 기존 코드를 이어받거나 이식하지 않는다.**
- 불만의 핵심: 기존 코드가 **Writing Workbench**(글감 작성용 Obsidian 플러그인/GitHub 라이브러리; 사용자 Vault에 설치됨)를 거의 그대로 닮았다. 새 제품은 그 화면 구성과 인터랙션을 모방하지 않는다.

### 디자인 참고 자료

- **Mylog 플러그인**(사용자의 다른 플러그인; 읽기 전용 참고): 흰 종이 바탕, 가는 선, 절제된 포인트 색, Pretendard 서체의 조용한 UI다. 분위기가 아니라 **마감 수준**(여백·타이포·선)만 가져온다. 분위기는 아날로그 작업실이다.
- **아날로그 글쓰기 오브제**: 필기구, 노트, 메모, 종이 질감 등의 분위기를 Pinterest 등 웹에서 조사해 디자인에 반영한다(디자인 단계 작업).

## 2. 목표

1. 작가가 메시지 한 문장을 확정하고 글의 얼개(후킹 → 나의 이야기 → 공통 경험 → 메시지)를 정하게 한다.
2. AI는 조수로 질문하고 글감을 찾는다. 주인공은 작가의 생각과 글감이다.
3. 글감이 코르크판에 포스트잇으로 하나씩 붙는 것이 실시간으로 보여 그 자체가 영감이 된다.
4. 쓰고 싶어지는 아날로그 작업 공간의 감성을 갖는다.

**비목표**: 채널별 글쓰기·발행·관리, 쓴 글 고치기(2단계), 마인드맵 화면, AI 모델·인증 선택 UI, API 키 방식 AI 연결.

## 3. 사용자

SNS에 꾸준히 글을 쓰는 작가 한 명. 자기 경험에서 출발해 공감받는 메시지를 만들고 싶다. 도구가 생각을 방해하지 않고 생각이 자라는 과정이 보이기를 원한다. Obsidian과 Claude Code를 이미 쓴다.

## 4. 전제와 제약

1. Obsidian **데스크톱**에서만 동작한다. 화면은 Obsidian 탭(ItemView) 안에 열린다.
2. **AI 기능은 사용자 PC에 설치·로그인된 Claude Code CLI(`claude`)를 플러그인이 실행해 호출한다.** API 키 입력은 없다. 따라서 **AI 기능(질문, 조사, 제안, 의견)을 쓰려면 Claude Code가 설치·로그인되어 있어야 한다.** 이는 배포 시 전제 조건이며 설치 안내문과 설정/첫 화면에서 알린다. AI 없이 가능한 기능은 FR-8.2가 정한다.
3. 글감 웹 검색도 Claude Code를 통한다(인터넷 필요). 카드 이미지는 Claude Code가 찾아 준 주소만 쓴다(FR-3.5).
4. 모든 UI 문구는 한국어. 다국어는 범위 밖.
5. 라이트·다크 테마 모두에서 아름다워야 한다.
6. 포스트잇용 한국어 필기체 글꼴은 **상업적 사용이 가능한 오픈 라이선스 글꼴 파일을 플러그인에 번들**한다(후보: 나눔손글씨 펜, 개구, 하이멜로디).
7. 정본은 Vault 안 마크다운 노트다. 플러그인 없이도 읽을 수 있어야 한다.
8. 지원 환경(제안값): macOS·Windows의 Obsidian 데스크톱. Linux는 검증 대상 아님. 최소 Obsidian 버전과 지원 Claude Code 버전은 §11.
9. 이 저장소 작업은 이 워크트리 안에서만 한다.

## 5. 범위

**포함**: 아이디어 목록·새 아이디어(두 시작점) / 역추적 대화 / 코르크판(AI 조사, 실시간 포스트잇, 직접 메모, 고정·버리기·보관함, 붉은 실 연결) / 후킹 설계와 템플릿 라이브러리 / 메시지·얼개 확정 / 초안 섹션 생성과 재확정 / 노트 저장·복원과 보존 규칙 / 아날로그 작업 공간 UI·키보드 조작 / Claude Code 미설치·실패 안내.

**제외**: 마인드맵 화면(카드 간 붉은 실만) / 초안 작성 화면 / 쓴 글 고치기 / 채널별 변환·발행·관리 / 포스트잇 글꼴 설정 변경 / Claude Code 외 AI 연결 / 모바일·다국어 / 기존 저장소 코드 재사용.

## 6. 용어

| 용어 | 뜻 |
|---|---|
| 아이디어 | 노트 하나로 저장되는 작업 단위 |
| 메시지 | 노트에 문장 1개 + 상태(후보/확정)로 저장. 질문형(물음표로 끝남)은 항상 「메시지 후보」 |
| 확정 메시지 | 상태가 「확정」인 메시지. **단언문만** 확정 가능 |
| 조각 | 「나의 이야기」의 한 토막(역추적 답 또는 직접 쓴 글) |
| 카드 | 코르크판 포스트잇. 「조사 카드」(AI가 찾음)와 「메모 카드」(직접 씀) |
| 얼개 | 네 **부분**(후킹, 나의 이야기, 공통 경험, 메시지)과 각 부분 안의 **항목**(한 줄 문구) |
| 단계 | 노트의 진행 상태: 작성 중 → 메시지 확정 → 얼개 확정 (FR-5.5) |
| 정의 id / 참조 | 항목을 만드는 `<!--cs:…-->` / 다른 항목을 가리키는 `<!--from:…-->`·`<!--ref:…-->` (FR-7.2) |

## 7. 사용 흐름

```
[열기] → 아이디어 목록 (항상 「새 아이디어」, 0개면 빈 상태)
  ├─ 메시지에서 시작 / 경험·글감에서 시작   (생성 직후 첫 질문 1회 자동 요청)
  ↓
  역추적 대화 → 조각이 쌓임 ─(「이야기 정리하고 다음으로」)→
  작업 메시지가 있으면 조사 제안 → 승인 → 포스트잇이 하나씩 붙음
  후킹 설계 → 메시지 확정 → 얼개 정리 → 얼개 확정 → 같은 노트에 「초안」 → 편집기에서 이어 씀
```

단계는 강요되지 않는다. 건너뛰거나 되돌아갈 수 있고 지금 할 수 있는 다음 행동이 늘 분명하다(확정 동작에는 FR-5 전제가 있다). 단계 이동 방식과 화면 배치는 디자인 단계에서 제안한다.

## 8. 기능 요구사항

### FR-1. 진입, 목록, 시작점

- FR-1.1 **진입·목록.** 리본 아이콘과 명령 「콘텐츠 스튜디오 열기」로 탭을 열면 첫 화면은 **아이디어 목록**이다. 목록에는 **아이디어 수와 관계없이 항상 「새 아이디어」(명령 포함)** 가 있고, 누르면 두 시작점(「메시지에서 시작」「경험·글감에서 시작」)을 고른다. 0개이면 빈 상태(한 줄 안내 + 두 시작 버튼)를 보인다. Claude Code를 쓸 수 없으면 같은 화면에 설치 안내 배너(FR-8.2). 작업 중 언제든 「아이디어 목록」으로 돌아가는 동작이 있다.
- FR-1.2 **생성.** 새 아이디어는 **아이디어 폴더**(설정)에 노트 하나를 만든다(폴더가 없으면 생성). 파일명은 입력(메시지 또는 경험 메모)의 앞뒤 공백을 뺀 앞 30자에서 `\ / : * ? " < > | # ^ [ ]`를 제거하고 끝의 점·공백을 뺀 것이며, 비면 「새 아이디어 YYYY-MM-DD HH-mm」다. 같은 이름이 있으면 " 2", " 3"을 붙여 **기존 노트를 덮어쓰지 않는다.**
- FR-1.3 **메시지에서 시작.** 사용자가 한 문장을 입력한다(해답 또는 질문). 질문형은 「메시지 후보」로 저장되며 역추적으로 단언문으로 다듬는다.
- FR-1.4 **경험·글감에서 시작.** 경험·글감(기사 링크, 메모)을 한 덩어리로 입력하면 「나의 이야기」 첫 조각이 된다(링크는 텍스트로 보존). 메시지는 비어 있어도 된다. **메시지 칸은 항상 보이고 직접 입력할 수 있다**(AI 없이도). 「메시지 제안 받기」를 누르면 AI가 단언문 후보를 최대 3개 내고, 각 후보의 「이 문장 쓰기」를 눌러야만 메시지 칸에 채워진다(상태: 후보).
- FR-1.5 **첫 질문 시점.** 아이디어를 **새로 만든 직후** AI가 가능하면 첫 질문을 1회 자동 요청한다(두 시작점 공통). 기존 노트를 열 때는 AI를 자동 호출하지 않는다(FR-2.3).
- FR-1.6 **메시지 수정.** 메시지는 언제든 고칠 수 있고 기존 카드·조각·후킹은 지워지지 않는다. 확정 상태에서 고쳤을 때의 전이는 FR-5.5.
- FR-1.7 **목록 범위와 추적.**
  - 목록은 아이디어 폴더(하위 폴더 포함)에서 frontmatter `content-studio: idea`를 가진 노트만 보인다. 항목마다 제목(메시지 또는 파일명)·단계·마지막 수정 시각을 보이고, 열면 이어서 작업한다.
  - 이름 변경·이동은 frontmatter `id`로 같은 아이디어로 추적한다(열린 화면은 새 경로로 계속 저장). **폴더 밖으로 옮기거나 아이디어 폴더 설정을 바꾸면** 그 노트는 목록에서 빠지되 노트는 그대로이며, 명령 「다른 위치의 아이디어 열기」(Vault 전체에서 `content-studio: idea` 노트 검색)로 연다. 설정 변경 시 기존 노트를 옮기지 않는다.
  - `id`가 없거나 frontmatter가 손상된 노트는 목록에 「식별 정보 없음」 경고로 보이고, 열면 읽기 전용이며 「식별 정보 복구」(새 id 발급)로 풀린다.
  - **같은 `id`의 노트가 둘 이상**(복제)이면 모두 목록에 「중복 id」 경고로 보이고, 열 수는 있으나 읽기 전용이다. 「새 id로 분리」를 누른 노트만 새 id를 받아 저장할 수 있다.
  - 열린 노트가 삭제되면 저장을 멈추고 진행 중 AI 요청을 끝내며(이후 결과 폐기) 「노트가 삭제되었어요」를 알린다. 화면 내용으로 다시 만들지는 사용자가 고른다.
- FR-1.8 **설정.** 아이디어 폴더, 후킹 템플릿 폴더, Claude Code 실행 파일 경로(기본: 자동 탐지)를 바꿀 수 있다.

### FR-2. 역추적 대화

- FR-2.1 AI는 **한 번에 질문 하나**만 한다(왜 그 메시지를 떠올렸는지, 과정과 장면을 거꾸로 되짚는 질문). 호출 지침에는 "개인 경험이 공통 경험으로 이어지는 질문도 할 수 있다"가 포함된다. 결과 형식은 FR-8.3.
- FR-2.2 답은 **조각**으로 쌓이며 사용자가 쓴 그대로 저장된다(AI가 다시 쓰지 않음). 조각은 질문 문구와 함께 저장되고, 수정·삭제·순서 변경·직접 추가가 가능하다.
- FR-2.3 진행:
  - 답을 제출하면 다음 질문을 요청한다(대기 중에도 다른 조작 가능). 「건너뛰기」는 그 질문을 저장하지 않고 다른 질문을 요청한다.
  - 조각을 수정·삭제해도 지난 질문은 안 바뀌고, **다음 질문부터** 남은 조각 전체가 맥락이 된다.
  - 대기 중 질문 하나는 노트에 저장되어 재시작 후 복원된다(AI를 다시 부르지 않음). 노트를 열었을 때 대기 질문이 없으면 「질문 받기」 버튼만 보이고 자동 호출하지 않는다.
  - 「이야기 정리하고 다음으로」를 누르면 진행 중 질문 요청을 중단하고 후킹·얼개 화면으로 간다(대기 질문은 저장된 채 남는다). 건너뛰기는 종료가 아니다.
  - AI를 쓸 수 없어도 조각은 직접 추가할 수 있다.
- FR-2.4 채팅 앱처럼 보이지 않는다(말풍선 누적 형태가 아니라 현재 질문과 조각이 중심). 판정은 D-1.

### FR-3. 코르크판

- FR-3.1 **조사 제안.** 조사는 **작업 메시지(후보·질문형 포함)가 비어 있지 않을 때만** 시작한다(없으면 「메시지를 먼저 적어 주세요」). AI는 「이 주제에 대해 조사해 볼까요?」를 제안하며, 사용자가 승인하거나 「조사하기」를 눌러야 시작한다(직접 요청은 승인). 승인 전에는 조사 호출이 없다.
  - **제안 규칙:** 메시지의 "변경 확정"(입력 칸을 벗어나거나 Enter로 값이 바뀜) 시점에, 현재 메시지가 `lastResearchMessage`(마지막으로 조사를 요청한 메시지)와도 `lastSuggestedMessage`(마지막으로 제안한 메시지)와도 다르면 제안하고 `lastSuggestedMessage`를 현재 값으로 한다. 거절해도 같은 문장에서는 다시 제안하지 않는다. 두 값은 노트에 저장되어 재시작 후에도 유지된다. 조사 요청을 시작하면 `lastResearchMessage`를 갱신한다. 조사 중 메시지가 바뀌면 제안은 조사가 끝난 뒤 한 번(FR-3.10).
- FR-3.2 조사는 웹 검색으로 사회 현상·데이터·사례·뉴스 등 공통 경험이 될 글감을 찾는다. **한 번에 카드 최대 8장(제안값)**; 「더 찾기」로 이어서 조사한다.
- FR-3.3 **실시간 추가.** 카드는 AI가 한 장을 완성해 내보내는 즉시 하나씩 붙는다. 모아 두었다가 일괄 연출하는 것은 허용하지 않는다. 플러그인은 카드를 받은 뒤 **1초 이내(제안값)**에 붙이고(애니메이션 0.6초 이내), 붙는 동안·조사 중에도 사용자는 판과 다른 요소를 조작할 수 있다.
- FR-3.4 **카드 필드.**

  | 필드 | 조사 카드 | 메모 카드 |
  |---|---|---|
  | 헤드라인 | 필수 | 선택(없으면 내용 첫 줄이 제목) |
  | 요약 | 필수 | — |
  | 내용 | — | 필수(1자 이상) |
  | 출처(이름+링크) | 필수(링크 http/https, 클릭하면 열림) | 선택 |
  | 메시지와 연결되는 이유 한 줄 | 필수 | 선택 |
  | 이미지 주소 | 선택(AI가 찾은 것만) | **없음** |
  | 상태 | 보통/고정/버림 | 보통/고정/버림 |

  요약은 AI에게 140자 이내(제안값)로 지시하고, 화면에는 최대 3줄까지 보이며 넘치면 말줄임, 카드를 열면 전문이 보인다. 사용자는 조사 카드의 헤드라인·요약·연결 한 줄을, 메모 카드의 모든 필드를 고칠 수 있다.
- FR-3.5 **이미지.** Claude Code가 조사 중 찾아 준 이미지 주소(URL)만 쓴다. 플러그인이 따로 검색하거나 내려받아 Vault에 저장하지 않고 주소로 표시만 하며 주소는 노트에 저장된다. 사용자가 이미지 주소를 직접 넣는 입력은 없다. 주소가 없거나 불러오지 못하면 이미지 없이 카드를 정상 표시한다.
- FR-3.6 **카드 동작.** 「얼개 후보로 고정」(고정 해제 가능; 고정은 얼개 채택 후보 지정일 뿐 얼개를 채우지 않음) / 버리기 / 두 카드를 **붉은 실**로 연결·해제(한 카드에 여러 실) / 위치 이동(저장됨). 마인드맵 화면은 없다.
- FR-3.7 **보관함.** 버린 카드는 **재시작 후에도 복구**할 수 있다. 판 한쪽 「버린 카드」 진입점(키보드로도 열림)에서 「복구」「완전히 삭제」(확인 후; 카드와 그 실이 노트에서 사라짐)를 한다.
  - 버릴 때: 위치와 직전 고정 상태를 기록하고, 고정은 풀린 채 보관함으로 간다. 붉은 실은 삭제되지 않고 보존되며 양끝 중 하나라도 버려지면 판에서 숨는다.
  - 복구할 때: 원래 위치로 돌아가되, 다른 카드와 겹치면 **원래 중심에서 나선형으로 카드 크기 격자 단위로 탐색한 첫 빈자리**(동률이면 위쪽, 그다음 왼쪽)로 간다. 고정 상태는 버리기 직전으로 돌아간다. 실은 양끝 카드가 모두 판 위에 있을 때 다시 보인다.
  - 버린 카드는 얼개 후보에서 빠진다. 이미 얼개에 복사된 내용은 영향이 없다(FR-5.2).
- FR-3.8 **메모 카드.** 내용만 있으면 직접 만들 수 있다(출처·연결 한 줄 불필요).
- FR-3.9 **진행 표시·중단.** 조사 중임을 표시하고 「중단」할 수 있다. 중단하면 요청을 끝내고 이후 도착 결과는 버리며 이미 붙은 카드는 남는다.
- FR-3.10 **조사 중 메시지 변경·늦은 결과.** 조사는 요청 시점의 아이디어 id와 기준 메시지를 기억한다. 조사 중 메시지가 바뀌어도 진행 중 조사는 원래 메시지 기준으로 계속하고 결과는 그 아이디어에 붙으며, 끝난 뒤 「새 메시지로 다시 조사할까요?」를 제안한다(승인 후 시작). 다른 아이디어로 이동·탭 닫기·비활성화 시 요청을 중단하고 이후 결과를 버린다(붙은 카드는 남음). 같은 종류의 AI 요청은 아이디어당 동시 1건이며 종류가 다르면(조사 중 질문) 동시에 가능하다.
- FR-3.11 **결과 분류.** 같은 출처 링크의 카드(버린 카드 포함)는 붙이지 않는다. 링크 비교는 스킴·호스트 소문자화, 끝의 `/`·`#fragment`·`utm_` 쿼리 제거 후 문자열 일치다. 한 요청의 결과는 다음으로 분류한다.

  | 수신 | 유효 | 신규(중복 제외) | 상태·안내 |
  |---|---|---|---|
  | 0건 | — | — | 「찾지 못했어요」 + 다시 조사 안내 |
  | 1건 이상 | 0건 | — | 실패(형식 오류) 안내 + 다시 시도 (FR-8.4) |
  | 1건 이상 | 1건 이상 | 0건 | 「이미 있는 글감뿐이에요」 |
  | 일부 무효 | 1건 이상 | 1건 이상 | 신규 카드는 붙고 「일부 글감을 가져오지 못했어요」 |

- FR-3.12 카드 **50장(제안값)** 에서도 판이 복잡해 보이지 않고 조작이 끊기지 않으며(NFR-3), **480px 폭에서도 전체 카드에 접근**할 수 있고(방식은 디자인에 맡김: 목록·미니맵·확대 등) 조사 중 새로 붙은 카드의 위치를 알 수 있으며 멀리 떨어진 두 카드를 연결할 수 있다.

### FR-4. 후킹 설계

- FR-4.1 **"A가 B를 한다"**: A(인물), B(행위), 이질성 메모, 정서·가치를 입력하면 후킹 후보의 하위 항목으로 저장된다. A와 B가 이질적일수록 끌린다는 원리에 따라 이질성을 함께 살피고, 정서·가치가 메시지로 이어지는지 본다.
- FR-4.2 AI는 요청하면 A·B 후보 제안, 이질성 피드백, 정서 회수 확인을 돕는다(결정은 사용자). 이질성 점수화는 미결정.
- FR-4.3 **기본 템플릿 8종**(이름, 설명, 예시):

  | 이름 | 설명 | 예시 |
  |---|---|---|
  | A가 B를 한다 | 인물(A)과 행위(B)가 이질적일수록 끌린다. 그 속 정서·가치가 메시지가 된다 | 은퇴한 소방관이 새벽마다 빵을 굽는다 |
  | 충격 | 예상을 깨는 사실이나 고백으로 시작한다 | 저는 하루 만에 구독자 3천 명을 잃었습니다 |
  | 일상적이지 않은 것 | 평범한 독자가 해 보지 않은 행동·장소로 시작한다 | 서울 한복판 엘리베이터에서 하루 종일 앉아 있어 봤습니다 |
  | 비틀기 | 통념을 뒤집어 말한다 | 열심히 하지 마세요. 오래 하세요 |
  | 숫자 | 구체적인 숫자로 신뢰와 호기심을 준다 | 하루 7분으로 3개월 만에 바뀐 것 세 가지 |
  | 궁금증 | 답을 알고 싶게 만드는 질문을 던진다 | 왜 가장 바쁜 사람이 가장 먼저 답장할까요? |
  | 비법 | 쓸 수 있는 방법을 알려 주겠다고 약속한다 | 제가 쓰는 첫 문장 공식을 공개합니다 |
  | 이유 설명 | 행동의 이유를 밝히겠다고 예고한다 | 제가 매일 같은 카페에 가는 이유는 단 하나입니다 |

- FR-4.4 사용자는 템플릿을 추가·수정·삭제한다. 템플릿은 **후킹 템플릿 폴더**(설정)에 **템플릿당 노트 하나**이며 파일명이 이름이다. 형식: frontmatter `content-studio: hook-template`, `format: 1`, `기본: true|false` + `## 설명` + `## 예시`(목록). Obsidian에서 직접 고치거나 추가·삭제하면 **2초 이내(제안값)** 반영된다. `## 설명`/`## 예시`가 없는 노트는 이름만 표시하고 경고를 붙인다.
- FR-4.5 **초기화.** 템플릿 폴더에 템플릿 노트(`content-studio: hook-template`)가 하나도 없고 기본 템플릿을 만든 적이 없으면 기본 8종을 만든다. **한 번 만든 뒤에는 자동으로 다시 만들지 않는다**(지운 템플릿은 재시작해도 되살아나지 않음). 설정의 「기본 템플릿 복원」은 없는 기본 템플릿만 만들고 기존 노트를 덮어쓰지 않는다. 폴더를 바꾸면 기존 노트를 옮기거나 지우지 않고, 새 폴더에 템플릿 노트가 없으면 확인 후에만 기본 8종을 만든다.
- FR-4.6 템플릿을 골라 현재 메시지·조각을 바탕으로 **후킹 후보**를 만든다(AI가 문장 후보 최대 3개 또는 직접 작성). **질문형 문장도 후보가 될 수 있다.** 후보는 여러 개 보관되고 템플릿 이름과 함께 저장된다. 후보가 얼개에 채택되었는지는 저장된 값이 아니라 "그 후보를 `from`으로 참조하는 얼개 항목이 있는가"로 계산한다.

### FR-5. 메시지, 얼개, 확정

- FR-5.1 얼개는 네 **부분**이며 **부분의 순서는 고정**이다: 후킹 → 나의 이야기 → 공통 경험(글감) → 메시지. 사용자는 부분을 옮기거나 지우거나 추가할 수 없고, 각 부분 안의 **항목**(한 줄 문구)만 이동·추가·삭제·수정한다.
- FR-5.2 **재료 채택은 복사다.** 조각·고정 카드·후킹 후보를 얼개에 채택할 때 재료별 한 줄 문구가 미리 채워지고 사용자가 확인·수정한 뒤 항목이 된다: 조각 → 첫 줄(최대 80자), 카드 → 헤드라인(없으면 내용 첫 줄), 후킹 후보 → 그 문장. 줄바꿈은 공백으로 바뀐다. 항목은 원본의 id를 `from`으로 기록하지만(표시용) 내용은 독립이다.
  - 원본을 수정·삭제하거나 카드를 버리거나 고정을 풀어도 얼개 항목은 바뀌지 않는다. 원본이 없으면 「원본 없음」으로 표시만 한다.
  - 같은 원본을 다시 채택하면 새 항목이 생긴다.
  - **예외(메시지 부분 첫 항목):** FR-5.3.
- FR-5.3 **메시지 부분 첫 항목 자동 채움.**
  - **최초 확정 때 한 번만** 확정 메시지를 메시지 부분 맨 앞 항목으로 채운다(새 id, `from`=메시지 id). 그 id는 `## 판 배치`의 `messageItem`에, 그때의 문장은 `lastConfirmedMessage`에 저장한다.
  - **재확정 때는 기존 항목을 덮어쓰거나 새로 끼우지 않는다.** 확정 메시지가 `lastConfirmedMessage`와 다르면 「메시지가 바뀌었습니다. 얼개 첫 항목을 갱신할까요?」를 묻기만 한다. 수락하면 그 항목의 문구만 바꾸고(id 유지) 거절하면 그대로 둔다. 어느 쪽이든 `lastConfirmedMessage`를 현재 문장으로 갱신해 되묻지 않는다. 사용자가 그 항목을 지웠거나 옮겼어도 새로 만들지 않고, 지웠으면 묻지 않는다.
  - 사용자가 최초 확정 전에 메시지 부분에 직접 쓴 항목은 그대로 두고 자동 항목이 그 앞에 들어간다.
- FR-5.4 AI는 요청하면 얼개의 빈 곳·어색한 흐름에 **의견**을 낸다. 얼개를 자동으로 바꾸지 않는다.
- FR-5.5 **확정 전제와 상태 전이.** 문장 판정은 앞뒤 공백 제거 후 한다.

  | 동작 | 확정 가능 | 불가와 안내 | 경고 후 진행 |
  |---|---|---|---|
  | 메시지 확정 | 비어 있지 않고 `?`·`？`로 끝나지 않음 | 비어 있음 → 「메시지를 적어 주세요」 / 물음표로 끝남 → 「질문은 메시지 후보로 두고, 해답 문장으로 바꿔 확정해 주세요」 | 줄바꿈 포함 또는 150자 초과 → 「한 문장으로 줄여볼까요?」 후 확정 가능 |
  | 얼개 확정 | 메시지 확정 상태이고, **(최초 확정이면 자동 채움 전 기준으로)** 네 부분 합산 항목이 1개 이상 | 메시지 미확정 → 「먼저 메시지를 확정해 주세요」 / 항목 0개 → 「얼개에 항목을 하나 이상 넣어 주세요」 | 비어 있는 부분이 있으면 「비어 있는 부분: …」 후 확정 가능(빈 부분은 초안 소제목 없음) |

  얼개 확정의 처리 순서: ① 전제 검사 → ② 메시지 항목 처리(FR-5.3) → ③ 초안 동기화(FR-6). 최초 확정에서 자동 항목만으로는 ①을 통과시키지 않는다. 재확정은 자동 항목을 포함해 센다.

  | 현재 단계 | 사용자 동작 | 결과 단계 |
  |---|---|---|
  | 작성 중 | 메시지 확정 | 메시지 확정 |
  | 메시지 확정 | 메시지 문장 수정 | 작성 중 (상태 후보로) |
  | 메시지 확정 | 얼개 항목 편집 / 얼개 확정 | 메시지 확정 / 얼개 확정 |
  | 얼개 확정 | 얼개 항목 이동·추가·삭제·수정 | 메시지 확정 (초안은 그대로) |
  | 얼개 확정 | 메시지 문장 수정 | 작성 중 (초안은 그대로) |
  | 얼개 확정 | 얼개 다시 확정 | 얼개 확정 (초안 재동기화) |
  | 모든 단계 | 초안 본문·카드·조각·후킹 편집 | 변화 없음 |

### FR-6. 초안 섹션

- FR-6.1 **첫 생성.** 얼개를 확정하면 같은 노트에 `## 초안`이 생기고 **얼개의 모든 항목이 얼개 순서대로 `###` 소제목**이 된다(부분 이름은 소제목이 아님, 빈 부분은 없음). 소제목 끝에 그 얼개 항목을 가리키는 참조 `<!--ref:xxxxxx-->`가 붙는다. 본문은 비어 있다.
- FR-6.2 **재확정(동기화)과 블록 규칙.** 어떤 경우에도 사용자가 쓴 본문 글자는 지워지지 않는다.
  - **영역·블록.** 초안 영역 = `## 초안`부터 다음 `# `·`## ` 제목 전까지. **관리 소제목** = `ref` 주석이 달린 `###` 줄. **관리 블록** = 그 줄부터 **같은 레벨 이하(`#`~`###`)의 다음 제목 전까지**이며, 하위 제목(`####` 이상)은 본문이다. 코드 펜스(```·~~~) 안의 `#`줄과 주석은 제목·id로 읽지 않는다.
  - **사용자 소제목** = `ref` 없는 `###`이고, 그 블록(다음 같은 레벨 이하 제목 전까지)은 **사용자 블록**이다. 첫 관리 소제목 앞의 텍스트와 사용자 블록은 **머리**로 맨 앞에 고정된다.
  - **위치 = 이웃 관계.** 관리 블록 뒤에 연달아 오는 사용자 블록들은 그 관리 블록의 **꼬리**가 되어 **그 관리 블록과 함께 이동**한다.
  - **동기화.** 얼개 항목 id와 `ref`를 맞춘다. **추가**: 얼개 순서에 맞는 자리에 새 소제목(빈 본문). **변경**: 소제목 문구만 바뀌고 본문은 그대로. **재정렬**: 관리 블록+꼬리가 새 순서로 이동하며 내용은 바이트 단위로 그대로다. **삭제**: 소제목 줄과 그 관리 블록 **자신의 본문**(꼬리 제외)이 대상이다. 본문이 비어 있지 않으면 문서의 `## 정리되지 않은 초안`(없으면 문서 끝에 새로 만들고, 있으면 그 자리에서 섹션 끝에 이어 붙임)으로 옮기고 옮긴 본문 위에 원래 소제목 문구를 `###`로 붙인다. 비어 있으면 소제목만 지운다. 삭제된 블록의 꼬리는 바로 앞 블록의 꼬리로 붙는다.
  - **예외.** 얼개에 없는 `ref`는 삭제로 처리한다. 같은 `ref`가 둘 이상이면 첫 번째만 관리 소제목이고 나머지는 사용자 소제목이다. 사용자가 관리 소제목을 지워 `ref`가 없는 항목은 새 소제목을 추가하며 남은 텍스트는 그대로 둔다. 초안 영역의 사용자 소제목에는 id를 붙이지 않는다. `## 초안` 밖의 사용자 `##` 섹션과 `## 정리되지 않은 초안`의 기존 내용은 건드리지 않는다.
  - 같은 얼개로 연속 재확정해도 결과가 같다.

  **예시.** 입력 상태: 얼개 후킹 `a1b2c3`, 나의 이야기 `d4e5f6`, `j0k1l2`(이 둘은 같은 부분). 초안은 다음과 같다(U1은 a1b2c3의 꼬리, U2는 d4e5f6의 꼬리).

  ````
  ## 초안
  ### 편의점 야간 알바생이 건넨 한마디 <!--ref:a1b2c3-->
  본문 A
  #### 본문 안의 작은 제목
  ```
  ### 코드 안의 줄(제목 아님)
  ```
  ### 내가 직접 붙인 소제목 1
  U1
  ### 사소한 친절에 무너진 날 <!--ref:d4e5f6-->
  본문 B
  ### 내가 직접 붙인 소제목 2
  U2
  ### 그날의 퇴근길 <!--ref:j0k1l2-->
  본문 C
  ````

  **재정렬** — 같은 부분 안에서 j0k1l2를 d4e5f6 앞으로 옮기고 재확정한 결과(d4e5f6은 꼬리 U2와 함께 뒤로 간다):

  ````

  본문 A
  #### 본문 안의 작은 제목
  ```
  ### 코드 안의 줄(제목 아님)
  ```

  U1
  ### 그날의 퇴근길 <!--ref:j0k1l2-->

  ### 사소한 친절에 무너진 날 <!--ref:d4e5f6-->

  **삭제** — 같은 입력에서 d4e5f6 항목을 얼개에서 지우고 재확정한 결과(본문 B는 이동, 꼬리 U2는 앞 블록 a1b2c3의 꼬리로 붙음):

  ````

  ### 편의점 야간 알바생이 건넨 한마디 <!--ref:a1b2c3-->
  본문 A
  #### 본문 안의 작은 제목
  ```
  ### 코드 안의 줄(제목 아님)
  ```
  ### 내가 직접 붙인 소제목 1
  U1
  ### 내가 직접 붙인 소제목 2
  U2
  ### 그날의 퇴근길 <!--ref:j0k1l2-->
  본문 C

  ## 정리되지 않은 초안

  ````

  **변경** — a1b2c3의 문구를 「야간 알바생이 건넨 한마디」로 고치면 첫 소제목 줄만 바뀌고 본문 A와 U1은 그대로. **추가** — 나의 이야기 부분 j0k1l2 뒤에 새 항목 `m3n4o5`를 넣으면 `### … <!--ref:m3n4o5-->`와 빈 본문이 j0k1l2 블록 뒤에 생긴다.
- FR-6.3 초안 본문은 Obsidian 편집기에서 쓴다. 초안 편집 화면은 없고, 플러그인은 FR-6.2가 정한 소제목 줄·블록 이동·`정리되지 않은 초안` 외에는 초안의 글자를 바꾸지 않는다.
- FR-6.4 확정 후 해당 노트를 편집기에서 여는 버튼과 명령이 있다.

### FR-7. 저장

- FR-7.1 **한 아이디어 = 노트 하나.** 구조(섹션 제목·키·라벨은 고정 규격; 서식 변화는 파서가 읽을 수 있는 한 허용). 아래는 모든 섹션이 채워진 상태의 예이며, 노트 생성 시에는 `## 초안`과 `## 정리되지 않은 초안`이 없고 FR-6.1·6.2가 만든다.

  ````
  ---
  content-studio: idea
  format: 1
  id: cs-7k2m9q            # 아이디어 id: Vault 전체에서 유일
  단계: 작성 중              # 작성 중 | 메시지 확정 | 얼개 확정
  시작점: 메시지              # 메시지 | 경험
  ---
  ## 메시지
  - 문장: 퇴근길의 작은 친절이 하루를 바꾼다 <!--cs:m4k2xa-->
  - 상태: 후보               # 후보 | 확정
  ## 나의 이야기
  - 편의점에서 있었던 일 <!--cs:d4e5f6-->
      - 질문: 그때 무슨 일이 있었나요?
  ## 글감
  ### 헤드라인 <!--cs:c3n8vb-->
  - 종류: 조사               # 조사 | 메모
  - 상태: 보통               # 보통 | 고정
  - 요약: …  / 내용: …(메모)  / 출처: [이름](https://…)  / 연결: …  / 이미지: https://…
  ## 버린 카드

  ## 얼개

  - 항목 문구 <!--cs:h5t9re--><!--from:a1b2c3-->

  ## 판 배치
  ```content-studio-board

   "pendingQuestion":"…","lastResearchMessage":"…","lastSuggestedMessage":"…",
   "lastConfirmedMessage":"…","messageItem":"g7h8i9"}
  ```
  ## 초안
  ### 소제목 <!--ref:h5t9re-->
  (사용자 본문)
  ## 정리되지 않은 초안
  ````

- FR-7.2 **소유권과 식별자.**
  - 플러그인 관리 영역: frontmatter의 `content-studio`·`format`·`id`·`단계`·`시작점`, `## 메시지`~`## 판 배치`. `## 초안`·`## 정리되지 않은 초안`은 **사용자 소유**(FR-6.2 외에는 쓰지 않음). 알려진 섹션 밖 텍스트는 그대로 둔다.
  - **항목 id** = 영소문자·숫자 6자. 정의 `<!--cs:xxxxxx-->`는 **노트 안에서 유일**(메시지·조각·카드·후킹 후보·얼개 항목). 다른 항목을 가리키는 `<!--from:xxxxxx-->`(얼개 항목→원본)와 `<!--ref:xxxxxx-->`(초안 소제목→얼개 항목)는 정의가 아니므로 유일성 대상이 아니다. 아이디어 id(`cs-` + 6자)는 Vault 전체에서 유일(FR-1.7).
  - 한 노트에 같은 정의 id가 둘 이상(복사·붙여넣기)이면 첫 항목이 id를 유지하고 나머지는 다음 저장 때 새 id를 받는다(이 사실은 알림). id 없이 편집기에서 새 항목 줄을 적으면 새 항목으로 보고 다음 저장 때 id를 붙인다(초안 영역의 사용자 소제목은 제외).
  - 카드 위치·붉은 실·진행 상태 값은 `## 판 배치` JSON 블록에만 둔다. JSON이 없는 카드·항목을 가리키는 키는 무시한다.
- FR-7.3 **자유 입력 왕복 문법.** 사용자 텍스트가 구조로 오인되지 않게 저장한다.
  - 여러 줄 값은 첫 줄을 항목에 쓰고 **이어지는 줄을 4칸 들여써서** 잇는다(빈 줄은 공백 4칸 줄). 항목 id 주석은 첫 줄 끝에 붙인다. 한 줄 값(얼개 항목·카드 헤드라인·템플릿 이름)은 줄바꿈을 공백으로 바꿔 저장한다.
  - 값의 각 줄에서 들여쓰기 뒤 첫 글자가 `#` `-` `*` `>` `` ` `` `~` `|` 또는 `숫자.`이면 앞에 `\`를 붙이고, 값 어디서든 `<!--`는 `<\!--`로 바꾼다. 읽을 때 되돌린다(그래서 사용자 텍스트의 `<!--cs:…-->`는 id가 아니다).
  - 왕복 예: 조각 입력 `## 제목처럼 보이는 줄⏎- 목록처럼⏎<!--cs:zzzzzz-->`는 다음처럼 저장되고 다시 읽으면 입력과 같은 텍스트가 된다.

    ```
    - \## 제목처럼 보이는 줄 <!--cs:d4e5f6-->
        \- 목록처럼
        <\!--cs:zzzzzz-->
    ```
  - 얼개 항목이 초안 소제목이 될 때도 같은 이스케이프를 쓴다(소제목은 한 줄).
- FR-7.4 **복원.** 닫았다 열거나 재시작해도 메시지(상태)·조각(질문)·대기 질문·카드(내용·위치·고정·버림)·붉은 실·보관함·후킹 후보·얼개 항목과 순서·단계·제안/확정 이력 값이 복원된다.
- FR-7.5 **외부 편집·손상.** 편집기에서 고친 내용은 **2초 이내(제안값)** 열린 화면에 반영된다. 어떤 항목·섹션을 읽지 못하면 **그 영역만** 「읽을 수 없는 부분」으로 표시하고 경고한다. 항목 경계 = 목록 줄과 4칸 들여쓴 이어지는 줄, 카드 경계 = `###` 블록, 섹션 경계 = 다음 `## `. 읽을 수 없는 영역의 원문은 **한 글자도 바꾸지 않고** 저장 때마다 그대로 둔다. `format`이 더 크면 읽기만 하고 「더 새로운 형식이에요」를 안내한다.
- FR-7.6 **저장과 병합.** 변경은 자동 저장되며 바뀐 항목만 갱신한다(파일 전체 재작성 금지, `Vault.process` 사용). 저장 직전 최신 디스크를 읽어 **항목 id 단위·순서·JSON 키 단위**로 병합한다.
  - 플러그인이 바꾼 항목만 적용하고, 디스크에서 다른 항목이 바뀌었으면 보존한다(같은 영역의 서로 다른 항목을 양쪽에서 고친 경우 둘 다 남음).
  - 같은 항목이 양쪽에서 바뀌었으면 **디스크(편집기) 쪽을 보존**하고 「편집기에서 바뀐 항목이 있어 그대로 두었어요」를 알린다(「내 입력 복사」로 플러그인 쪽 입력을 가져옴). 외부에서 삭제된 항목에 대한 플러그인 수정은 삭제를 우선한다(알림). 순서는 디스크 순서가 마지막으로 읽은 것과 같을 때만 플러그인의 순서 변경을 적용한다.
  - 초안 본문은 플러그인 저장으로 바뀌지 않는다.
- FR-7.7 **저장 실패.** 실패하면(잠김·읽기 전용·삭제 등) 「저장 안 됨」을 계속 표시하고 내용을 메모리에 유지하며 다음 변경과 「다시 저장」으로 재시도한다. 재시도도 최신 디스크에 FR-7.6을 적용한다. 미저장 변경이 있는 채 목록 이동·다른 아이디어 열기·탭 닫기·종료를 하면 「저장하지 못한 변경이 있어요」와 「내용 복사」「다시 저장」「그래도 나가기」를 보인다. 디스크의 원문을 지워 실패를 해결하지 않는다.

### FR-8. AI 연결 (Claude Code CLI)

- FR-8.1 **실행 계약.** 로컬 `claude`를 **비대화형·스트리밍 출력**으로 실행해 JSON을 받는다(옵션은 지원 CLI 버전에 맞춤).
  - 실행 위치: 플러그인이 만든 **빈 임시 폴더**(Vault 밖). 허용 도구: 읽기 전용 도구와 **웹 검색(웹 페이지 읽기 포함)** 뿐이며 쓰기·셸·MCP는 불허. Vault 파일은 플러그인만 쓴다.
  - 허용 목록 밖 권한이 필요해지면 **자동 거절**하고 사용자 승인을 기다리며 멈추지 않는다. 그로 인해 결과를 못 얻으면 FR-8.4의 실패다.
  - 보내는 내용은 호출에 필요한 것(메시지, 조각, 고정 카드의 헤드라인·요약, 후킹 후보, 선택 템플릿 등)뿐이며 다른 노트는 보내지 않는다. 지침에 "한국어로 답한다"를 넣는다.
- FR-8.2 **상태 확인·안내.** 첫 사용과 설정에서 확인한다. 오류 분류 우선순위: ① 명령 없음 → 「설치 필요」, ② 미로그인 → 「로그인 필요」, ③ 네트워크 오류 → 「네트워크 확인」, ④ 그 밖의 비정상 종료·분류 불가 → 「실행 실패」(원인 출력 일부 표시). 각각 한국어로 원인과 해결 방법을 안내한다. AI를 쓸 수 없어도 **AI 없이 가능한 기능**(아이디어 만들기, 메시지·조각·메모 카드·후킹·얼개 직접 편집, 확정, 초안 생성)은 계속 쓸 수 있다.
- FR-8.3 **결과 수용 계약.** 호출 종류별로 정해진 JSON만 받고, 검증을 통과한 것만 반영한다.

  | 종류 | 출력 | 검증·처리 |
  |---|---|---|
  | 질문 | `{"questions":["…"]}` | 비면 실패. 2개 이상이면 첫 번째만 쓰고 나머지는 버림 |
  | 글감 카드 | 한 줄 JSON을 스트리밍: `{"type":"card","headline","summary","source":{"name","url"},"connection","image"?}` 이후 `{"type":"done"}` | 필수 필드 누락·링크가 http/https 아님이면 그 카드만 버리고 계속. 완성된 한 줄을 파싱하는 즉시 반영. `done` 없이 스트림이 끝나면 단절로 처리 |
  | 메시지 후보 | `{"candidates":["…"]}` (최대 3) | 질문형 문장은 제외. 4개 이상이면 앞 3개 |
  | 후킹 후보 | `{"candidates":["…"]}` (최대 3) | **질문형도 허용.** 4개 이상이면 앞 3개 |
  | A·B 제안/피드백 | `{"suggestions":[{"a","b"}],"feedback":"…"}` | 없는 키는 빈 값으로 |
  | 얼개 의견 | `{"opinion":"…"}` | 얼개를 바꾸지 않음 |

  부분 실패: 도중에 끊기면 검증을 통과해 반영된 결과는 남기고 못 받은 부분을 알리며 「다시 시도」를 준다. 재시도는 새 요청이며 FR-3.11 중복 규칙을 적용한다. 질문은 재시도해도 대기 질문 하나를 교체할 뿐 쌓이지 않는다.
- FR-8.4 **생명주기·지연·실패·중단.**
  - 요청은 아이디어 id와 맥락 스냅샷(메시지·조각·템플릿 등)을 기억한다. **질문**은 요청 후 메시지·조각이 바뀌면 결과를 폐기하고(「질문 받기」로 다시 요청), **후보·의견·제안**은 도착한 결과를 보이되 「바뀌기 전 내용 기준이에요」를 붙인다. 노트 삭제·아이디어 전환·탭 닫기·비활성화 시 모든 요청을 끝내고 늦은 결과를 버린다. 같은 종류 요청은 아이디어당 동시 1건.
  - 지연(제안값): 질문·메시지 후보·후킹 후보·A·B 제안·얼개 의견은 **30초** 후 「오래 걸리고 있어요」(중단 가능), **120초**에 시간 초과. 조사는 첫 카드가 **60초** 안에 없으면 같은 안내, 전체 **300초**에 시간 초과.
  - 실패(오류·시간 초과·권한 거절·형식 오류·네트워크)는 원인을 한국어로 알리고 「다시 시도」를 준다. 입력한 내용은 보존된다. 사용자는 언제든 중단할 수 있으며 중단 시 프로세스를 끝내고 이후 결과를 버린다.
- FR-8.5 **외부 통신.** 사용자 작업 내용을 외부로 **보내는** 경로는 Claude Code 호출과 그 웹 검색뿐이다. 플러그인 자체의 네트워크 요청은 카드 이미지 주소를 표시하려고 읽어 오는 것(내용 전송 없음)뿐이며 이미지는 저장하지 않는다. 출처 링크는 클릭할 때만 열린다.
- FR-8.6 플러그인 비활성화·Obsidian 종료 시 실행 중인 CLI 프로세스를 모두 끝낸다.

### FR-9. 화면·UX 기준

- FR-9.1 **전체가 아날로그 작업 공간**(종이, 책상, 코르크, 포스트잇, 필기구 오브제)이되 **Mylog 수준의 여백·타이포·선의 완성도**를 지키고 화면이 복잡해지지 않는다. 판정은 D-2.
- FR-9.2 지금 무엇을 하면 되는지가 늘 분명하다. 상태별(최초 진입, 아이디어 0개, 메시지 없음, 질문 대기, 빈 판, AI 대기·실패, 확정 후) 다음 행동 안내가 있다. 클릭 수가 적다. 대표 과업의 클릭 수 상한(제안값): 새 아이디어 만들기 3회, 조사 승인 1회, 카드 고정 1회.
- FR-9.3 **핵심 동작은 키보드만으로 가능하다**: 열기, 새 아이디어(두 시작점), 목록으로 돌아가기, 질문 답하기·건너뛰기·정리하고 다음으로, 조사 승인·중단, 카드 선택(방향키/Tab)·고정·버리기·연결·연결 해제, 보관함 열기·복구, 템플릿 고르기·후킹 후보 채택, 얼개 항목 이동·추가·삭제, 단계 이동, 메시지·얼개 확정, 초안 열기. 이 동작은 모두 명령 팔레트 명령으로도 등록되어 단축키를 지정할 수 있다. 포커스는 항상 보이고 화면을 열면 첫 입력 요소에 놓인다.
- FR-9.4 AI는 조수다. 작가의 입력이 중심이며, 직접 편집 중·질문 없음·AI 대기·실패 상태에서는 질문이 강조되지 않는다.
- FR-9.5 라이트·다크 모두에서 감성이 유지되고 모든 텍스트가 읽힌다. 테마 변경을 따른다.
- FR-9.6 포스트잇 글씨는 **번들된 필기체**이며 시스템에 글꼴이 없어도 같다. 그 외 UI는 읽기 좋은 본문 서체(디자인 단계에서 정함).
- FR-9.7 **최소 탭 폭 480px(제안값)** 에서 가로 스크롤·잘림이 없고 긴 카드는 열어 볼 수 있으며 FR-3.12가 성립한다.
- FR-9.8 플러그인이 제공하는 **고정 UI 문구**(버튼, 안내, 오류, 설정, 명령 이름)는 모두 한국어다(제품명·고유명사 제외; AI 생성·사용자 입력·웹 원문은 검사 대상 아님).

### FR-10. 디자인 산출 조건

- 라이트·다크 각각의 시안 세트: 최초 진입(빈 상태), 목록, 역추적 대화, 코르크판(카드 8장 이상·붉은 실), 보관함, 후킹 설계, 얼개·확정, 오류 안내(미설치·AI 실패), 480px 대표 화면.
- Pinterest 등 레퍼런스 조사와 반영 기록, 글꼴 라이선스 확인 기록.
- Writing Workbench와 기존 저장소 화면의 비모방 확인(D-4).

## 9. 비기능 요구사항

- NFR-1 설치·활성화·비활성화가 정상 동작하고 비활성화·삭제해도 Vault 노트는 남는다.
- NFR-2 사용자 동작(클릭·키 입력)에 대한 화면 반응은 AI 응답과 무관하게 즉시(0.1초 이내, 제안값)다. AI 지연 수치는 FR-8.4.
- NFR-3 카드 50장(제안값) 판에서 이동·고정·버리기의 화면 반영이 0.1초 이내(제안값)이며 조사 중에도 같다.
- NFR-4 사용자가 쓴 내용을 임의로 삭제·덮어쓰지 않는다(FR-6.2, FR-7.5~7.7).

## 10. 완료 기준

### 10.1 검증 방법과 대역 시나리오

- **[실행]** 플러그인을 실제로 실행해 예/아니오로 판정. AI 의존 기준은 **테스트용 `claude` 대역**(설정의 Claude Code 경로로 지정; 고정 응답을 내는 실행 파일)으로 판정한다. **[점검]** 코드·통신(실행 인자, 네트워크 요청, 파일 쓰기 경로) 검토 + 근거 기록. **[디자인]** 시안을 10.4 체크리스트로 검토하고 **Jake의 서면 승인**으로 판정(비교 자료나 승인이 없으면 "판정 유보"이며 합격이 아니다).
- 시간 측정 기준: 입력 이벤트 시각 → 변경이 화면에 그려진 시각을 개발자 도구 타이머/로그로 기록하고 20회 중 19회 이상이 기준 이내면 합격. 검증 OS·Obsidian 버전·장비를 기록한다.

| 번호 | 대역 시나리오 |
|---|---|
| S1 | 정상: 질문 1개, 카드 3장(필수 필드 완비)+`done`, 메시지·후킹 후보 각 3개(후킹 후보 중 물음표로 끝나는 문장 1개 포함), A·B 제안, 얼개 의견 |
| S2 | 지연 스트리밍: 카드 1 즉시, 카드 2는 5초 뒤, 카드 3은 10초 뒤, 그동안 프로세스 실행 유지 |
| S3 | 질문 2개: `{"questions":["Q1","Q2"]}` |
| S4 | 카드 3장 중 1장 필수 필드 누락, 1장 링크가 http/https 아님, 1장 정상(이미지 주소 접속 불가) |
| S5 | 중단 요청 2초 뒤에도 카드 한 장을 더 내보냄 |
| S6 | 카드 1장 후 `done` 없이 비정상 종료. 재시도하면 같은 카드를 다시 포함 |
| S7 | 응답 없음(무한 대기) |
| S8a/b/c/d | 명령 없음(경로 없음) / 종료코드 1+출력에 `not logged in` / 종료코드 1+출력에 `network error` / 종료코드 1+그 외 출력 |
| S9 | 허용되지 않은 권한을 요청하는 이벤트 출력 후 오류 종료 |

### 10.2 기준

**진입·시작·목록**
1. [실행] 리본/명령으로 탭이 열리고 첫 화면은 목록이다. **아이디어가 1개 이상일 때도 「새 아이디어」가 있고** 눌러 두 시작점을 고를 수 있다. 0개면 한 줄 안내와 두 버튼의 빈 상태.
2. [실행] 「메시지에서 시작」으로 단언문을 입력하면 아이디어 폴더에 노트가 생기고 frontmatter에 `content-studio: idea`·`format: 1`·`id`가 있다. 같은 제목이면 " 2" 노트가 생기고 기존 노트는 그대로다. 파일명에 쓸 수 없는 문자가 제거된다. 폴더 설정을 바꾸면 새 노트가 그 폴더에 생긴다. 생성 직후 첫 질문 요청이 대역에 1회 기록되고, 기존 노트를 열 때는 기록이 늘지 않는다.
3. [실행] 물음표로 끝나는 문장으로 시작할 수 있고 「메시지 후보」로 표시되며 「메시지 확정」은 FR-5.5의 안내와 함께 거부된다.
4. [실행] 「경험·글감에서 시작」: 메모가 첫 조각이 되고 메시지 없이 진행되며 메시지 칸에 직접 입력할 수 있다. S1의 「메시지 제안 받기」 후보 3개는 「이 문장 쓰기」 전에는 메시지 칸을 바꾸지 않고, 누르면 후보 상태로 채운다.
5. [실행] 목록은 `content-studio: idea` 노트만 보이고 단계·수정 시각이 있다. 이름 변경·이동 후에도 열린 노트가 계속 저장된다. 폴더 밖으로 옮기거나 폴더 설정을 바꾸면 목록에서 빠지되 노트는 그대로이고 「다른 위치의 아이디어 열기」로 열린다. 열린 노트를 삭제하면 안내가 나오고 저장·AI 요청이 멈춘다. `id`가 없는 노트는 경고+읽기 전용+「식별 정보 복구」, `id`가 같은 노트 둘은 둘 다 경고+읽기 전용+「새 id로 분리」 후 한쪽만 저장 가능.

**저장·복원**
6. [실행] FR-7.4의 모든 상태가 재시작 후 그대로 복원된다.
7. [실행] 편집기에서 FR-7.1의 한국어 섹션 제목 아래 내용이 읽히고 id는 숨은 주석뿐이다. 다음 입력으로 왕복한다: 조각 `## 제목처럼 보이는 줄⏎- 목록처럼⏎<!--cs:zzzzzz-->`, 코드 펜스·`~~~`·`|` 시작 줄, 여러 줄 메시지. 저장→재시작→읽기 후 텍스트가 입력과 같고 섹션·항목·id로 오인되지 않으며 FR-7.3의 저장 예와 같은 모양으로 저장된다.
8. [실행] 편집기에서 카드 하나의 필수 필드를 지워 손상시키면 그 카드만 「읽을 수 없는 부분」이 되고 나머지는 정상이며, 다른 항목을 저장해도 손상 영역의 원문은 **바이트 단위로 같다**. 편집기 변경이 2초 안에 반영된다. `format`을 더 크게 바꾸면 읽기만 된다. 같은 정의 id를 가진 두 항목을 만들면 첫 항목이 id를 유지하고 둘째가 새 id를 받는다.
9. [실행] 병합: ① 같은 섹션의 서로 다른 두 조각을 편집기와 플러그인에서 각각 고치면 둘 다 남는다. ② 같은 조각을 양쪽에서 고치면 편집기 쪽이 남고 알림·「내 입력 복사」가 동작한다. ③ 편집기에서 삭제한 조각을 플러그인에서 고치면 삭제가 유지되고 알림이 나온다. ④ 편집기에서 항목 순서를 바꾼 뒤 플러그인에서 다른 항목을 고쳐도 편집기 순서가 유지된다. ⑤ 판 배치 JSON의 서로 다른 카드 키를 양쪽에서 고치면 둘 다 남는다.

### 10.4 디자인 검토 체크리스트 (판정: Jake의 서면 승인)

대상은 FR-10의 시안 세트. 하나라도 "아니오"이면 불합격이다. 필요한 비교 자료(Mylog·Writing Workbench·기존 저장소 화면 캡처)가 제공되지 않았으면 해당 항목은 판정 유보다.

- **D-1 대화 화면**: (a) 말풍선이 누적되는 메신저 형태가 아니다. (b) 답변 대기 상태에서 현재 질문이 가장 눈에 띄고, 직접 편집·질문 없음·AI 대기·실패 상태에서는 작가의 입력 영역이 중심이다. (c) 조각이 같은 화면에 보인다. (d) 입력 칸 옆에 「건너뛰기」와 「이야기 정리하고 다음으로」가 있다.
- **D-2 아날로그 감성의 절제**: (a) 모든 화면에 종이·코르크·필기구·메모 질감이 하나 이상 있다. (b) 입력·읽기 영역 위에 장식이 겹치지 않는다. (c) 한 화면의 장식 오브제 종류가 4개 이하(제안값). (d) 간격 단위와 선 굵기가 몇 가지 기준으로 통일됨이 시안에 명시된다. (e) Mylog 화면 캡처와 나란히 놓고 여백·타이포·선 마감이 같은 수준이라는 Jake의 판단이 승인 기록에 있다.
- **D-3 라이트/다크**: (a) 일반 텍스트 대비 4.5:1 이상. (b) 포스트잇 글씨와 바탕 대비 4.5:1 이상. (c) 포스트잇 글씨 16px 이상, 본문 14px 이상(제안값). (d) 두 테마에서 같은 분위기. (e) 선택·포커스·비활성 상태가 두 테마에서 구분된다.
- **D-4 비모방**: (a) Jake가 Writing Workbench 대표 화면 캡처 5장 이상과 기존 저장소 대표 화면 캡처 5장 이상을 제공한다. (b) 시안과 나란히 두고 레이아웃(패널 배치)·주요 컴포넌트·상호작용 흐름을 각각 "다르다/비슷하다"로 기록한다. (c) "비슷하다"에는 이유와 바꾼 내용을 적는다. (d) Jake가 "겹치지 않는다"고 승인한다.
- **D-5 다음 행동**: 최초 진입(Claude Code 상태 포함), 아이디어 0개, 아이디어 1개 이상의 목록(새 아이디어), 메시지 없음, 질문 대기, 정리하고 다음으로, 빈 코르크판(조사 가능/불가), AI 대기, AI 실패, 메시지 확정 후, 얼개 확정 후 각각에서 다음 행동이 글과 버튼으로 시안에 있다. 대표 과업 클릭 수(FR-9.2)가 상한 이하다.
- **D-6 좁은 폭(480px)**: D-5의 상태와 카드 열람·연결·보관함 진입·50장 접근(FR-3.12)이 가능한 시안이다.
- **D-7 산출물 완비**: (a) FR-10의 시안 세트 전부(라이트·다크), (b) 레퍼런스 조사·반영 기록, (c) 기준 52의 글꼴 기록이 있다.

## 12. 확정 사항 (논의 후 결정됨)

- **카드 이미지**: Claude Code가 찾아 준 주소만 사용, 직접 검색·저장 없음, 실패 시 이미지 없이 표시. 메모 카드에는 이미지 필드가 없다. (FR-3.4~3.5, 8.5, 기준 18·41)
- **버린 카드**: 재시작 후에도 복구되는 보관함. 버림/복구 시 위치·고정·붉은 실 규칙 확정. (FR-3.7, 기준 21)
- **메모 카드**: 출처·연결 한 줄 없이 만들 수 있다. (FR-3.4·3.8, 기준 17·19)
- **얼개 재료 채택은 복사**다. (FR-5.2, 기준 31)
- **메시지 첫 항목**: 최초 확정 때 한 번만 채우고, 재확정 때는 덮어쓰거나 끼우지 않으며 메시지가 바뀌었으면 갱신 여부를 묻기만 한다(수락 시 문구만 변경, id 유지). (FR-5.3, 기준 32)
- **재확정**: 사라진 얼개 항목의 소제목 아래 본문은 삭제하지 않고 문서의 「정리되지 않은 초안」 섹션으로 옮긴다. (FR-6.2, 기준 34)
- **Claude Code 권한**: 읽기 전용+웹 검색만 허용, Vault는 플러그인만 씀, 실행 위치는 Vault 밖 임시 폴더, 권한 요청은 자동 거절. (FR-8.1, 기준 40)
- **확정 메시지는 단언문만**; 질문형은 「메시지 후보」. 확정 전제·빈 필드 허용·상태 전이는 FR-5.5 표. 얼개 네 부분은 순서 고정이고 부분 내부 항목만 이동·추가·삭제. (FR-5.1·5.5, 기준 3·30·32)
