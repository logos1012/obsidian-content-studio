# 콘텐츠 스튜디오 디자인 독립 검토

검토일: 2026-10-30 · 대상: kraken / nautilus / leviathan의 `index.html` · 검토자: 프로젝트 사전 맥락이 없는 새 독자.

**필수 화면의 종류는 세 시안을 합치면 라이트·다크 모두 존재한다. 그러나 하나의 제품 흐름으로 승인할 상태는 아니다. 차단 3건, 중요 7건, 사소 3건이다.** 공통 팔레트와 손글씨는 잘 이어지지만, 화면 간 이동과 데이터 맥락이 끊긴다. 코르크판 밖, 특히 다크 얼개·초안은 아날로그 원고보다 일반적인 어두운 폼/목록 앱에 가깝다. Mylog와 동등한 마감인지, 기존 제품과 겹치지 않는지는 비교 자료와 Jake의 서면 승인 없이 확정하지 않는다.

## 검토 방법과 증거의 한계

- 기준은 요청한 PRD §1, §7, FR-1~5, FR-8 오류 안내, FR-9~10, §10.4다. 저장소 열람은 `docs/PRD.md`와 지정한 세 시안 폴더로 제한했다. 다른 디자인 베이스·과거 리뷰·참고 자료 폴더는 읽지 않았다.
- Orca 내장 브라우저에 각 `file://…/designs/<이름>/index.html`을 직접 열었다. `snapshot` → `click`/`eval` → `screenshot --format png --json`을 사용했고, `result.data`를 PNG로 저장하여 열어 보았다. 브라우저 실행은 `/Applications/Orca.app/Contents/Resources/bin/orca`를 사용했다. 기본 `/usr/local/bin/orca`는 앱 경로 해석에 실패했다.
- 먼저 화면과 상태를 보았고, 이후 세 `NOTES.md`를 읽었다. NOTES의 자기 검증·승인 주장과 검토자의 직접 관찰은 구별했다. 필요한 곳에만 해당 HTML/CSS 및 번들 OFL 파일을 보조 근거로 확인했다.
- 모든 테마·480px 토글을 사용했다. kraken은 최초 진입/목록/판, Claude Code 없음, 판/목록, 보관함, 재등장 동작을 확인했다. nautilus는 질문 대기/질문 없음/AI 대기/AI 없음/AI 실패를 각각 두 테마와 두 폭으로 확인했다. 후킹과 라이브러리도 두 테마·두 폭으로 확인했다. leviathan은 장면 4종과 오류 4종을 각각 두 테마·두 폭에서 확인했다. 장면×오류의 모든 교차 조합을 전수검사한 것은 아니다.
- 기본 화면은 1200px 뷰포트와 시안의 480px 컬럼 토글을 사용했고, 추가로 **실제 뷰포트 폭 480px**에서 대표 화면·입력 포커스·카드 열람·연결 시작·라이브러리·재확정 창·초안 결과를 확인했다. 대표 상태에서 `innerWidth = scrollWidth = 480`이었다.
- 긴 스크롤에서 화면이 비거나 캡처가 반복되는 Orca 현상이 있었다. 높이를 2200~3200px로 늘려 확인했고, 하단은 상단 도구/헤더나 앞부분을 **브라우저 DOM에서만 임시 숨겨** 다시 확인했다. `*-hidden.png`, `*-result-full.png`는 그런 보조 캡처다. 숨긴 화면으로 원래 배치의 밀도·첫 화면 노출을 합격 처리하지 않았다. 일부 캡처의 반복 띠·검은 여백·테마 직후 일시적 버튼 도색은 제품 잘림 결함으로 세지 않았다.
- 시안 파일은 수정하지 않았다. 실제 Claude Code 호출, Vault 저장·복원, Obsidian 명령 팔레트, 전체 키보드 과업, 50장 부하, 모든 대비 픽셀은 검증하지 않았다. HTML 시안의 모의 응답을 실제 AI 동작으로 간주하지 않는다.

증거는 [screenshots](screenshots/)에 있다. 파일명 `480`은 시안의 컬럼 토글, `actual480`은 실제 뷰포트 480px, `1200`은 넓은 뷰포트다. 대비/크기 보조 측정은 같은 폴더의 `*-metrics.json`에 있다.

## B. §10.4 체크리스트

§10.4 제목 자체가 최종 판정을 ‘Jake의 서면 승인’으로 정한다. **D-1~D-7 최종 승인 판정은 모두 판정 유보**다. 아래 소항목의 합격/불합격은 검토자의 관찰 판정이며 Jake의 승인을 대신하지 않는다. 특히 D-2(e), D-4의 비교 자료 부재는 유보이고, 관찰된 결함까지 자료 부재로 숨기지는 않았다.

| 항목 | 최종 판정 | 검토 의견 |
|---|---|---|
| D-1 대화 화면 | 판정 유보 | 관찰한 a~d는 합격. 입력 중심 상태 전환이 가장 잘 정리된 화면이다. 480px에서는 조각이 첫 화면 아래로 멀어진다. |
| D-2 아날로그 감성의 절제 | 판정 유보 | a/b/d는 대체로 합격, c는 엄격 집계 시 불합격. e는 비교 자료·승인 부재로 유보. 다크 얼개의 아날로그 인상은 약하다. |
| D-3 라이트/다크 | 판정 유보 | a/b는 다크 메모 배지 대비 때문에 불합격, c는 카드의 14px 라벨 때문에 문언대로는 불합격. d는 색 분위기 유지, e는 관찰 범위에서 구분됨. |
| D-4 비모방 | 판정 유보 | 비교 캡처 각 5장과 Jake 승인 미제공. NOTES의 구조 비교만으로 합격할 수 없다. |
| D-5 다음 행동 | 판정 유보 | 관찰 적합성은 불합격. 시작 이후 첫 질문, 화면 간 복귀·연속 이동, 메시지 없는 조사 불가 상태가 빠져 있다. |
| D-6 480px | 판정 유보 | 대표 배치는 양호하나 관찰 적합성은 불합격. D-5의 누락이 이어지고 50장 접근·원거리 연결 상태를 확인할 시안이 없다. |
| D-7 산출물 완비 | 판정 유보 | a의 화면 종류는 있음. b는 반영 메모만 확인, 원 조사 검증 유보. c 글꼴 기록은 있음. 전체 상태와 비모방 승인까지 완비됐다는 결론은 불가. |

| D-3(d) 같은 분위기 | 합격(테마 간) | 종이/밤 종이와 붉은 포인트, 밝은 포스트잇을 유지한다. 다크 얼개의 아날로그 인상이 약한 문제는 D의 별도 의견에 남겼다. |
| D-3(e) 선택·포커스·비활성 구분 | 합격(관찰 범위) | 테마/단계의 선택, nautilus의 비활성 이동, 입력의 붉은 포커스, kraken 연결 시작의 점선이 구별된다. [연결 포커스](screenshots/kraken-actual480-dark-link-focus.png). 전체 키보드 과업은 미검증이다. |

대비 수치는 `orca eval`로 얻은 계산 색과 조상 배경의 알파 합성에 상대 휘도를 적용했다. 질감·그라데이션·스크린샷의 모든 픽셀과 비활성 상태를 인증한 값은 아니다. kraken 라이트 정상 텍스트 표본 최저 약 4.62, nautilus 라이트/다크 약 5.01/5.54, leviathan 약 5.01/5.08이었다. 비교하는 표본 화면은 서로 같지 않으므로 시안 순위를 매기는 숫자가 아니다.

## D. 전체 아날로그 작업 공간과 Mylog 수준의 마감

| 화면 | 아날로그 작업 공간에 대한 검토 의견 |
|---|---|
| 최초 진입·목록 | 종이 바탕과 작은 코르크/포스트잇 표식이 있어 제품 방향은 드러난다. 목록은 충분히 간결하다. 다크 목록은 작은 표식을 빼면 범용 텍스트 목록에 가까워, 제목과 날짜의 위계를 조금 더 분명히 할 필요가 있다. |
| 역추적 | 가장 설득력 있다. 질문 한 장·작가의 입력·남은 조각의 구성이 차분하며 노란 메모가 작업실의 온도를 준다. 다만 480px에서는 제품 메시지·제목·질문·노란 메모·메시지 제안까지 지나야 조각을 만나므로 상단 여백이 작업 재료를 멀리 밀어낸다. |
| 코르크판 | 물성과 붉은 실의 의미가 가장 명확하다. 핀은 고정을, 테이프는 일반 카드를 구별한다. 반면 사진·네 가지 종이색·기울기·접힌 모서리·테이프·핀·강조 문장까지 겹쳐 상대적으로 밀도가 높다. 9장에서도 카드 제목, 본문, 출처, 연결 이유, 실 연결명이 모두 경쟁한다. 50장은 더 강한 정리가 필요하다. |
| 보관함·카드 열람 | 읽기에는 편하지만 평범한 모달 시트 인상이 강하다. 종이의 따뜻한 색과 가는 선이 전체 시스템을 최소한 유지한다. 전문의 본문체 전환은 타당하다. |
| 후킹 | 노란 메모·필기체 공식과 평면 입력지가 균형을 이룬다. 다크의 큰 A/B 폼은 일반 설정 폼처럼 보이는 구간이 있다. 안내 메모보다 작가의 문장과 후보 사이 관계가 더 강하게 보여야 한다. |
| 얼개·확정·초안 | 가장 약하다. 라이트는 큰 원고지 같은 면으로 읽히지만 다크는 검은 배경+둥근 패널+리스트+붉은 버튼이 지배한다. 필기체 제목과 희미한 배경 결만으로 작업실 느낌을 유지하기 어렵다. [다크 결과](screenshots/leviathan-actual480-dark-result-full.png)는 일반 다크 앱처럼 보일 우려가 크다. 재료 가져오기 창의 밝은 메모는 좋지만 평상시 화면에 지속되지 않는다. |
| 오류 | 원인을 짧게 읽고 작업으로 돌아갈 수 있는 leviathan 구조가 좋다. 황색 경고가 제품의 재료색과 겹치므로 경고 제목·아이콘/문구로 상태를 명료하게 구별해야 한다. |

Mylog와의 **동급 마감 판정은 유보**다. 독립적으로 볼 때 글줄과 선은 정돈되어 있고 과도한 사이드바·채팅 UI도 없다. 개선 우선순위는 소품 추가가 아니라, 다크 원고 면의 종이색/가장자리/행 리듬을 분명히 하고 메시지·단계·작업 제목을 공통 위계로 정리하는 것이다. 장식 오브제를 추가하면 판의 4종 제한과 간결함 문제가 더 커진다. 읽기 면에 노이즈를 얹는 방식은 피하고, 작업지 주변과 재료를 놓는 방식으로 아날로그 성격을 유지하는 편이 적절하다.

### 잘림·가로 넘침·가독성·키보드·한국어 점검 범위

- **잘림/가로 넘침:** 실제 480px 대표 상태에서 문서 가로 넘침은 발견하지 못했다. 카드 요약 3줄·메모 5줄·연결 이유 2줄의 말줄임은 의도된 축약이며 전문 창은 열렸다. 장문 입력·모든 문구 길이·모든 창 높이를 전수검사한 것은 아니다. Orca 캡처의 빈 영역/반복은 제품 결함과 분리했다.
- **가독성:** 손글씨 본문은 충분히 크지만 같은 크기의 본문체보다 작게 보인다. 출처/배지의 크기와 다크 메모 배지 대비는 F-04/05다. 모든 카드에 붙은 연결 이유·실 연결명까지 상시 노출하면 정보 밀도가 높아진다.
- **키보드 포커스:** nautilus 입력의 붉은 링을 양 테마에서 보았고, kraken에서 `L`로 연결 모드·점선 원점·Enter 안내를 보았다. leviathan 갱신 창에서 Tab/Enter로 조작했다. 카드 전문은 Escape로 닫혔다. 모달을 제외한 전체 순회, 50장 방향키 탐색, 모든 명령 팔레트 등록은 **못 봤다**. 포커스가 모든 핵심 과업에서 항상 보인다고 합격할 수 없다. 단계/목록 복귀가 없는 곳은 키보드로도 경로가 없다(F-02).
- **한국어 문구:** 직접 본 버튼·상태·폼·오류·라이브러리에 제품 고유명사/키 이름/A·B 공식 이외의 불필요한 영어 고정 문구는 발견하지 못했다. 한국어 문구 누락은 **설치·실패의 원인/해결(F-06)**, 메시지 없는 판의 조사 불가/입력 유도(F-01)다. 설정·명령 팔레트는 시안에 없어 확인하지 못했다.

## 승인 전에 남는 증거

Jake의 Mylog 마감 비교 및 비모방 서면 승인, Writing Workbench/기존 저장소 각 5장 대조는 여전히 필요하다. 이는 사용자가 제공하지 않은 자료에 관한 유보이며 위 3개 차단 결함과 별개다. 다음 검토에서는 연결된 동일 아이디어 흐름, 빈 메시지/빈 판 상태, 480px 50장 과업을 먼저 확인하는 것이 적절하다.
