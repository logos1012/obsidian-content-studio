# kraken 시안 — 뼈대·디자인 시스템·코르크판

# 현재 상태 요약 (4차 기준 — 먼저 읽는 곳)

## 지원하는 것
- 화면: 최초 진입(빈 목록)·아이디어 목록·코르크판·보관함. 라이트/다크, 480px(실제 창 폭 또는 `w480=1`).
- 판: 9장/50장, 순서 칸 자동 배치, 카드 찾기(`/`)·전체 지도·위치 표시, 붉은 실 잇기/풀기(원거리는 목록에서 고르기), 자리 옮기기(`M`+방향키 / 끌어서 놓기), 고치기(`E`), 버리기·보관함 복구, 선택 카드 동작줄.
- **카드 고정은 1클릭**: 카드에 마우스를 올리거나 선택/초점이 가면 카드 안에 「고정」(고정 중이면 「풀기」) 버튼이 보인다. 목록 보기(480px)에서는 항상 보인다. 키보드 `P`도 그대로.
- 오류 4종(미설치·로그인 안 됨·실패·네트워크)을 규약 §6 구조로 표시. 카드 안 글자는 모두 16px 이상, 배지 대비 4.5:1 이상.
- **판 상태 프리셋(시안 보기 도구의 「판 상태」, 또는 `?preset=`)**: `nomsg`(메시지 없음 + 빈 판, 경험 시작 직후), `empty`(메시지만 있고 빈 판), `noresearch`(조사 불가=Claude Code 미설치), 기본은 보통. `?message=none`은 `preset=nomsg`와 같다 — 경험·글감 시작에서 코르크판으로 이어질 때 nautilus가 `../kraken/index.html?view=board&message=none`으로 보내면 된다(시안 간 링크는 이번에 바꾸지 않음). 빈 판에는 안내 상자(조사하기·메모 붙이기·메시지 적기)가 나온다.
- 쿼리: `view`, `theme`, `w480`, `cards=50`, `ai=missing|login|fail|net`, `preset`.

## 지원하지 않는 것
- 카드를 판 위 임의 좌표에 두는 자유 배치(순서 칸 기반), 새로고침 뒤 상태 저장, 복구 시 나선형 빈자리 탐색.
- 다른 시안(nautilus/leviathan) 폴더가 이 워크트리에 없어 단계·시작점 링크는 열리지 않는다(주소 문자열만 규약대로).
- 설치 명령 문구는 공식 안내와 대조하지 않았다. Pretendard 미번들, Gaegu 서브셋 미실시.

## 오브제 집계 (D-2c, 4종)
**종이(바탕·원고 면) / 코르크(판) / 포스트잇(카드) / 붉은 실** = 4종. 고정 표시의 「핀」은 별개 오브제가 아니라 **붉은 실의 매듭**이다: 실 양 끝의 매듭 점(`.t-knot`)과 고정 카드 위의 점이 같은 색·같은 모양(평평한 `--thread` 원)이며, 고정 카드에서 실이 이어지는 것처럼 읽힌다. 입체 그라데이션 핀 머리는 없앴다(3차까지는 실과 핀을 따로 세어 5종). 카드는 장식 없음, 고정 카드만 매듭 하나.

# 이력 (1~3차 기록 — 현재와 다를 수 있음, 위 표 참고)

산출: `index.html` (단일 파일, 열면 바로 보임) + `fonts/` (Gaegu Regular·Bold, OFL.txt).
상단의 점선 줄은 **시안 확인용 임시 네비게이션**이며 제품 UI가 아니다(화면 전환, 라이트/다크, Claude Code 없음, 480px 보기, 카드 붙는 동작 다시 보기).

## 검증 상태
2차에서 Orca 내장 브라우저로 직접 열어 스크린샷을 보고 점검했다(viewport 1016×838, 480px 보기). 캡처는 `screens/`에 있다. 1차에 적었던 "화면 미확인" 단서는 해소됐다. 남은 한계는 아래 "2차 점검 결과".

## 디자인 결정과 이유
1. **단일 작업면.** 목록 → 판 → (이후) 대화·후킹·얼개를 한 화면씩 전환. 3열·우측 AI 패널·말풍선을 쓰지 않았다. 판 화면 상단은 「현재 메시지(손글씨 34px)」+ 5단계 이동(이야기·코르크판·후킹·얼개·초안)+「다음: 후킹 설계」 하나로 정리했다.
2. **장식 오브제 4종만:** 종이(바탕 질감 ~5%), 코르크(판에만), 포스트잇, 붉은 실/핀. 입력·읽기 영역(목록, 시작 폼, 대화상자, 조사 제안 줄)은 평평한 `--surface` 위 1px 선만 쓴다. 그림자는 포스트잇과 모달에만.
3. **포인트 색은 붉은 실 하나**(`#B83A32` / 다크 `#E0675C`). Mylog 주황 태양 모티프는 쓰지 않았다.
4. **카드 의미를 색·장식으로 분리:** 분홍 = 내가 쓴 메모 카드, 노랑·하늘·연두 = 조사 카드. 보통 카드는 마스킹 테이프, **고정 카드는 붉은 핀 + 「얼개 후보」 배지 + 더 높은 그림자**(색에만 의존하지 않음). 붉은 실은 카드 뒤로 지나가 글자를 가리지 않는다(핀 위치만 보임).
5. **조사 제안은 판 위의 한 줄**(「이 주제를 조사해 볼까요?」 + 조사하기/나중에). 진행 중은 같은 줄이 「조사하는 중이에요 · N장 붙었어요 [중단]」으로 바뀐다. 새 카드는 「새로」 배지가 7초 보이고 화면 밖이면 스크롤로 따라간다(FR-3.12 새 카드 위치).
6. **480px / 50장:** 컨테이너 쿼리로 폭 기준 동작. 720px 미만이면 자동으로 **목록 보기**(같은 카드를 세로로, 붉은 실은 카드 안에 「붉은 실: 연결된 카드명」으로 표기)로 바뀌고, 「판/목록」 토글로 언제든 전환. 멀리 떨어진 카드 연결은 키보드(L → 방향키 → Enter)로 가능. 미니맵·확대는 이번 라운드에 넣지 않았다.
7. **토큰:** 간격 4·8·12·16·24·32px, 선 1px/1.5px 두 가지, 반경 4·8·14px 세 가지 — 모두 `:root` 변수. 라이트/다크 모두 정의, 포스트잇은 다크에서도 밝은 종이(밝기만 낮춤). 다크의 스탠드 빛은 판 모서리 radial 1개.
8. **키보드:** Tab/방향키(공간 기준 이동)로 선택, `P` 고정, `X`·Delete 버리기, `L` 실 잇기/풀기(이미 이어진 카드를 고르면 해제), `Enter` 열기, `B` 보관함. 포커스 링은 2px 붉은색(오프셋 4px)이며 선택 상태와 같은 모양, 실 잇는 중인 카드는 점선. 동작 결과는 스크린리더용 live region과 토스트로 알린다. 버린 직후 토스트에 「되돌리기」.
9. **등장 동작:** 카드가 위에서 살짝 기울어 내려와 붙고(0.52초) 170ms 간격으로 하나씩 등장, 실은 양끝이 붙은 뒤 그려진다. `prefers-reduced-motion`이면 생략.

## 2차 점검 결과 (Orca 내장 브라우저, 라이트·다크 캡처 확인)

캡처: `screens/{light,dark}-{empty,list,board,archive,narrow}.png` (최초 진입 / 목록 / 코르크판 / 보관함 / 480px 코르크판). 코르크판 캡처는 스크롤 300px 위치(상단 단계줄 일부 + 조사 제안 + 판)다.

### 고친 것
1. **판 오른쪽 카드 잘림·가로 넘침.** 원인은 판 캔버스가 1180px 고정이었던 것. 폭에 맞춰 열 수를 정하는 자동 배치(`layout()`)로 바꿨다(카드 폭 224~268px, 열 사이 56px). 1016px에서 3열, 가로 스크롤 없음(`scrollWidth == innerWidth` 확인), 판 안 스크롤바도 없앴다(판 높이는 내용에 맞고 페이지가 스크롤된다). 카드는 순서대로 가장 낮은 열에 붙는다. 중간 폭(720~1000px)은 2~3열로 줄어든다. 1000px 이상 넓은 폭은 열 수만 늘어나는 같은 규칙이며 이 환경의 창이 1016px라 그 이상은 직접 보지 못했다.
2. **붉은 실이 카드에 가려져 안 보임.** 자동 배치로 카드 사이가 좁아져 핀 위치 기준 실이 모두 카드 뒤로 숨었다. 실이 서로 마주 보는 모서리에서 나와 이어지도록 바꾸고 굵기를 2.5px로 올렸다. 실은 여전히 카드 뒤를 지나므로 글자를 가리지 않는다.
3. **가독성.** 포스트잇 손글씨 17→18px, 카드 제목 19→21px. 「메시지와」 강조색 `#8A2A24`→`#74201B`(다크 분홍 포스트잇 위 4.3:1 → 5.3:1). 계산한 대비(WCAG 상대 휘도 기준): 라이트 본문 13.3, 보조 5.0~5.5, 포인트 글자 5.1, 버튼 흰 글자 5.7; 다크 본문 15.5, 보조 5.7~6.2, 버튼 5.5; 포스트잇 본문(#2B2621) 라이트 12.2~, 다크 분홍 7.5; 포스트잇 보조(#4A4037) 최저 5.5; 「메시지와」 최저 5.3. 모두 4.5:1 이상. 화면에서 라이트·다크 모두 포스트잇 글씨가 또렷함을 확인했다.
   - **손글씨 최소 크기 원칙:** Gaegu는 같은 px에서 시스템 서체보다 작아 보이므로, 포스트잇 손글씨 **본문 18px 이상(최소 16px)**, 제목 21px 이상, 현재 메시지 34px(좁은 폭 27px), 목록 제목 23px로 둔다. 14px 이하 손글씨는 쓰지 않는다. 포스트잇 안의 출처·배지·「붉은 실:」 줄은 본문 서체 14px이다.
4. **최초 진입(빈 상태).** 두 시작 버튼이 맨 글자만 있었다 → 각각 한 줄 설명이 붙은 두 카드(「메시지에서 시작」은 붉은 테두리로 기본 제안)로 바꿨다. 눌러서 문장/글감 입력 → 「시작하기」로 이어진다(클릭 3회 이내).
5. **아이디어 목록.** 「새 아이디어」가 상단 오른쪽에 항상 있고, 누르면 같은 두 시작점이 펼쳐진다(목록 0개일 때와 같은 구성). 제목 옆에 작은 코르크+핀 로고를 넣어 종이 질감 외 오브제가 보이게 했다. 단계는 3칸 막대+글자로, 「식별 정보 없음」 경고 항목과 「식별 정보 복구」 버튼을 확인했다.
6. **보관함.** 버린 카드 시트(`버린 카드 N`/`B`로 열림)에 카드별로 「복구」「완전히 삭제(확인 후)」, 「버리기 전 고정이었어요」·「붉은 실 N개 숨김」 칩, 상단 안내문(복구하면 원래 자리와 고정 상태로 돌아가고 숨은 실도 다시 보임)을 넣었다. 동작 확인: 버리면 실이 숨고 복구하면 같은 순서 자리·같은 고정 상태로 돌아오며 실이 다시 보인다(카드 배치가 순서 기반이라 원래 자리와 같다).
7. **480px 코르크판.** 목록 보기로 자동 전환, 카드 한 열, 「붉은 실: 이어진 카드명」 표기, 가로 넘침 없음 확인. 단계 이동 5칸이 두 줄로 꺾이던 것을 한 줄로 줄이고 「다음」 버튼은 폭 전체로 바꿨다.
8. 새로고침 시 브라우저가 복원하던 임시 체크박스(480px, Claude Code 없음)를 초기화했다.

### 못 고친 것 / 남은 한계
- **긴 페이지 스크롤 상태 캡처 불가.** Orca 내장 브라우저가 스크롤 800px 이상에서 화면을 비우거나 일부만 그려서(도구 한계로 추정, 페이지 문제는 아님), 480px 목록 아래쪽 카드는 상단 요소를 숨긴 뒤 캡처해서 확인했고 `screens/`에는 스크롤 0~300px 상태만 저장했다. 판 아래쪽(3행 이후)의 붉은 실·새 카드는 화면으로 확인하지 못했다.
- 카드를 순서 기반으로 자동 배치하므로 **카드 위치를 직접 옮기는 기능과 위치 저장은 이 시안에 없다**(FR-3.6 위치 이동은 구현 단계에서). 이에 따라 복구 시 나선형 빈자리 탐색도 시연하지 않는다.
- 50장 부하는 확인하지 않았다. 판이 길어지므로 구현 시 미니맵이나 새 카드 이동 보조가 필요하다.
- 코르크판 최상단은 임시 네비게이션+메시지+단계+조사 줄 때문에 판이 첫 화면(838px 높이)에 3분의 1만 보인다. 실제 Obsidian 탭에서는 임시 네비게이션이 없으므로 더 올라오지만, 메시지 영역을 줄일지는 Jake 판단이 필요하다.
- 480px 캡처는 이 환경의 1016px 창 가운데에 480px 컬럼을 둔 것이다(실제 480px 창 아님). 임시 네비게이션이 열이 좁아 세 줄로 접힌다(제품 UI 아님).
- 「메시지와: …」 줄이 카드마다 있어 카드 높이가 커진다. 조사 카드 요약이 3줄 말줄임이라 전문은 카드를 열어야 한다(의도).
- Pretendard 미번들, Gaegu TTF 서브셋 미실시는 1차와 같다.


## 3차: 공통 규약(docs/design/CONTRACT.md) 적용 + 담당 결함 (F-01, F-03, F-04·05, F-06, F-10, F-12, F-13)

캡처(`screens/`): `{light,dark}-{empty,list,board,archive,board50,error,find,edit}.png`는 1016×1300 창, `-narrow`, `-narrow-list`, `-narrow-error`, `-narrow50`은 **실제 480px 폭 창**이다. (Orca 브라우저는 스크롤 800px 이상에서 화면을 비우는 문제가 있어 `set viewport`로 창 높이를 늘려 스크롤 없이 찍었다. 전환 애니메이션은 캡처 때만 꺼 두었다.)

### 규약 적용
- **쿼리 파라미터:** `view=list|empty|board|archive`, `theme=light|dark`, `w480=1`을 읽는다(추가로 `cards=50`, `ai=missing|login|fail|net`는 검토용). 화면을 옮기거나 테마·폭을 바꾸면 주소창도 같이 갱신하고, 다른 시안으로 가는 모든 링크에 현재 theme·w480을 이어 붙인다.
- **공통 헤더(§2):** 「← 아이디어 목록」(`?view=list`) · 가운데 「콘텐츠 스튜디오」(Gaegu 22px) · 오른쪽 「퇴근길의 작은 친절」. 목록·빈 목록 화면에서는 같은 자리에 제품명만 보인다(위치 고정).
- **단계열:** `1 이야기 — 2 코르크판 — 3 후킹 — 4 얼개 — 5 초안`, 번호 원+연결선. 현재=붉은 채움 원+밑줄, 지나온 단계=붉은 테두리·연한 채움 원, 아직=빈 원. 각 단계는 규약 주소로 가는 실제 링크(`../nautilus/index.html?step=story|hook`, `../leviathan/index.html?step=outline|draft`). 480px에서는 현재 단계만 이름을 보이고 나머지는 번호(스크린리더용 이름 유지)로 한 줄에 들어간다.
- **현재 메시지:** 「현재 메시지」+ 알약 배지(후보/확정)+ 항상 보이는 「수정」 버튼, Gaegu 32px(480px 26px). 수정은 제자리 입력 칸. 메시지가 비면 「아직 메시지가 없어요. 한 문장으로 적어 보세요」 입력 칸이 나오고 조사 제안은 「메시지를 먼저 적어 주세요」로 바뀐다.
- **타이포(§4):** 화면 제목(「아이디어」「아직 아이디어가 없어요」)은 본문 서체 굵게 28px(필기체 제목 제거). 필기체는 현재 메시지·포스트잇·제품명·목록의 메시지 문장에만. 본문 16px, 보조 14px 이상. 다이얼로그 제목·조사 제안 문구도 본문 서체로 바꿨다.
- **용어:** 후보/확정, 카드 「고정」(핀), 「얼개 후보로 고정」(동작), 「조사하기」. 「얼개 후보」 배지는 「고정」으로 맞췄다.
- **원고지 면(§5):** 목록·빈 목록·오류 상자·시작 폼은 `--surface` 면 + 1px 가장자리 + 약한 그림자, 목록 행은 가는 줄(`--rule`)로 나눈다. 읽는 글 아래에는 질감 노이즈를 깔지 않는다. 다크 면은 `#211F1C`로 배경보다 한 단계 밝고 따뜻하게 바꿔 구분했다.

### 결함별
- **F-01 (두 시작점 → nautilus 역추적):** 「메시지에서 시작」「경험·글감에서 시작」은 입력 폼을 거쳐 `../nautilus/index.html?step=story&start=message|experience&text=<입력>&theme=…`로 이동한다(경험 시작은 text 없이도 가능). 시작 버튼 문구는 「시작하기 — 첫 질문 받기」. 형제 폴더가 이 워크트리에는 없어 이동 자체는 열리지 않는다(통합 폴더에서 검증 필요). 메시지 없는 판은 위 「메시지를 먼저 적어 주세요」 상태로 보인다(판 화면에서 「수정」으로 메시지를 지워 확인하려면 입력을 비우고 저장 시도 → 안내; 실제 빈 상태 화면은 이번에 따로 두지 않았다).
- **F-03 (50장):** 도구 모음의 「카드 수 9장/50장」(또는 `?cards=50`)으로 50장 상태를 만든다. ① **카드 찾기**(`/`, 버튼): 제목·요약·내용 검색 + 전체 목록, 각 줄에 색·고정·위치(「3열 · 위에서 11번째」, 목록 보기에서는 「목록 31번째」), 고르면 그 카드로 스크롤·선택. ② **위치 표시**: 선택 카드 동작줄에 「50장 중 31번째 · 위치」, 판 오른쪽 아래 **전체 지도**(점=카드, 붉은 테두리=고정, 붉은 사각형=지금 보이는 곳, 누르면 이동), 새 카드는 「새로」 배지+지도 깜빡임. ③ **원거리 연결**: `L`로 연결을 시작한 뒤 「목록에서 고르기」(`/`)로 어디에 있든 이을 카드를 골라 잇거나 푼다. 480px 목록 보기에서도 같은 찾기·연결을 쓴다.
- **F-04·F-05 (배지 대비, 16px):** 카드 안 모든 글자(배지·출처·「메시지와」·「붉은 실」)를 16px 이상으로 올렸다. 배지는 모든 카드색 위에서 같은 어두운 알약(`#2B2621` 바탕, `#FFF6D6` 글자 약 14:1)과 고정 배지(`#8F2A24` 바탕 흰 글자 8.3:1)로 바꿔 라이트·다크 모두 4.5:1 이상이다. 카드 밖 동작 줄·버튼은 본문 서체 14~16px.
- **F-06 (kraken 오류):** 규약 §6 구조(제목 → 원인 한 줄 → 해결 방법 번호 목록 → 「조사 없이도 메모 카드는 직접 붙일 수 있어요」 계속 작업 → 「다시 확인/다시 시도」·「직접 쓰기로 계속」)의 공통 오류 상자를 만들었다. 미설치(설치 명령·경로 설정·재확인)/로그인 안 됨/AI 실패/네트워크 오류 네 가지. 도구 모음 「AI 상태」로 전환하며, 판에서는 조사 제안 자리, 목록·빈 목록에서는 화면 맨 위에 같은 상자가 나온다. 색은 노랑을 쓰지 않고 제목·「!」 아이콘·두꺼운 테두리로 구분한다. 이전의 설치 토스트·노란 배너는 없앴다. 설치 명령(`npm install -g @anthropic-ai/claude-code`)은 공식 안내 확인 없이 쓴 시안 문구이므로 구현 때 확인이 필요하다.
- **F-10 (고치기·위치 이동):** 카드 전문 창에 「고치기」(`E`)가 있고 조사 카드는 헤드라인·요약·연결 한 줄만, 메모 카드는 모든 칸(출처 링크는 http/https 검사)을 고친다. **위치 이동:** 판은 폭에 맞춰 카드를 순서대로 칸에 정렬하므로 「자리 = 순서 칸」으로 정의했다. 키보드는 카드에서 `M` → `←→` 한 칸, `↑↓` 한 줄 → `Enter` 확정/`Esc` 취소(방향키 선택 이동과 구분되는 별도 모드이며 상단에 안내가 뜬다). 마우스는 카드를 끌어 다른 카드 위에 놓기. 동작줄의 「자리 옮기기」 버튼도 같다. 시안에서는 새로고침하면 순서가 초기화된다(저장 안 함).
- **F-12 (오브제·밀도):** 오브제를 **종이·코르크·포스트잇·붉은 실·핀 5종**(규약 범위)으로 줄였다: 마스킹 테이프와 접힌 모서리를 없애 보통 카드는 장식 없음, 고정 카드는 핀 하나. 집계 기준: 한 화면에서 서로 다른 오브제 종류 수. 카드별 동작 줄을 없애고 판 위쪽 하나의 「선택한 카드 동작줄」(스크롤해도 따라옴)로 합쳐 카드 안 요소를 줄였다. 카드 이미지 높이 92→76px.
- **F-13 (빈 목록의 「새 아이디어」):** 최초 진입(빈 목록)도 목록 화면과 같은 구성 — 같은 자리·같은 이름의 「새 아이디어」 버튼이 있고 두 시작점이 열려 있으며(아이디어가 있는 목록에서는 버튼을 눌러야 펼쳐짐) 아래에 「아직 아이디어가 없어요」 안내.

### 못 고친 것 / 남은 한계
- 다른 시안 폴더가 없어 단계 링크·시작점 이동은 이 워크트리에서 열리지 않는다(주소 문자열만 규약대로 확인).
- 위치 이동은 순서 칸 기반이라 카드를 판 위 임의의 좌표에 두는 자유 배치는 아니다(PRD FR-3.6의 “위치 이동”을 자유 좌표로 해석하면 부족). 복구 시 나선형 빈자리 탐색은 시연하지 않는다(순서 기반이라 원래 자리로 돌아감).
- 480px에서 50장 카드를 고르면 sticky 동작줄이 4줄 높이를 차지한다. 더 줄이려면 동작 이름을 아이콘화해야 하나 이번에는 글자를 유지했다.
- 480px는 실제 480px 창으로 확인했고 `w480=1`(1016px 창 가운데 480 컬럼)은 같은 규칙이지만 캡처하지 않았다.
- 포스트잇 손글씨는 18px로 읽히지만 Gaegu 특성상 같은 크기 본문체보다 작아 보인다(규약 최소는 충족).
- 판 아래쪽 카드와 붉은 실, 미니맵 클릭 이동은 눈으로 보지 못한 부분이 있다(창 높이 1300px 안에서만 확인).
